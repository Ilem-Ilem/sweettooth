Stock Movement Data Fix - Summary
Issue
Error: "Class 'manualadjustment' not found" when accessing the Stock Movement Analytics page.
Root Cause
The database contained invalid referencetype values (manualadjustment, approvaladjustment) that were not valid Eloquent model classes, causing Laravel's morphTo relationship to fail when trying to resolve the polymorphic relationship.
Changes Made
Database Data Cleanup
Removed all rows with invalid referencetype values:
  - Converted manualadjustment entries (with NULL referenceid) to NULL
  - Converted approvaladjustment entries (with no corresponding model) to NULL
  - Converted empty string referencetype values to proper NULL
Fixed SuperAdmin Purchase Creation 
File: app/Livewire/SuperAdmin/Inventory/Purchases.php (Lines 203-215)
Problem: StockMovement was being created with wrong/non-existent fields:
itemid (doesn't exist in schema)
branchid (doesn't exist in schema)
movementtype (should be type)
recordedby (should be movedbytype and movedbyid)
Solution: Updated to match correct schema and properly track who created the movement:
php
StockMovement::create([
    'stockid' => $stock->id,
    'type' => 'in',                                    // ✓ Correct field
    'quantitybefore' => $quantitybefore,             // ✓ Added
    'quantityafter' => $stock->quantityavailable,    // ✓ Added
    'quantity' => $quantity,
    'referencetype' => 'App\Models\Purchase',         // ✓ Full class path
    'referenceid' => $purchase->id,
    'movedbytype' => getclass(Auth::user()),        // ✓ Changed from recordedby
    'movedbyid' => Auth::id(),                       // ✓ Changed from recordedby
    'movementdate' => $this->purchasedate,
    'notes' => 'Purchase: ' . $purchaseNumber,
]);
Added Purchase → StockMovement Relationship
File: app/Models/Purchase.php
Added a proper relationship to link purchases with their stock movements:
php
public function stockMovements(): HasMany
{
    return $this->hasMany(StockMovement::class, 'referenceid')
        ->where('referencetype', 'App\Models\Purchase');
}
Verified StockMovement Model
File: app/Models/StockMovement.php
The morphTo relationship is correctly configured:
php
public function reference(): MorphTo
{
    return $this->morphTo(FUNCTION, 'referencetype', 'referenceid')
        ->withDefault(null);  // Returns null if reference doesn't exist
}
