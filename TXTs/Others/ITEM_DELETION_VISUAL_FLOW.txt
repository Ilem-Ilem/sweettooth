Data Flow Diagram
REQUEST SUBMISSION
==================
User Deletes Item "Flour"
        │
        ├─► gatherRelatedDataForDeletion()
        │   ├─ RecipeIngredient.where(itemid=5).get()
        │   │   └─ Finds: [Bread recipe, Cake recipe]
        │   │       └─ Via recipe: [Wheat Bread, Cup Cake]
        │   ├─ Item.stocks().get()
        │   │   └─ Finds: 5 stock records
        │   ├─ Item.purchaseItems().get()
        │   │   └─ Finds: 3 purchase orders
        │   └─ Stock.stockMovements().get()
        │       └─ Finds: 47 movements
        │
        ├─ showDeletionConfirmationDialog()
        │   └─ Shows summary to user
        │
        └─► submitItemDeletionRequest()
            └─ InventoryApprovalService::requestItemDeletion()
                └─ Creates ApprovalAuditRequest with payload
                    └─ payload['relateddata'] = gathered data
                        └─ AuditService logs with summary
APPROVAL PROCESS
================
Admin views approval request
        │
        ├─► openDetailsModal()
        │   └─ Fetches ApprovalAuditRequest
        │       ├─ requester info
        │       ├─ action: "deleteitem"
        │       ├─ description: reason
        │       └─ payload: {
        │           itemid: 5,
        │           relateddata: { recipes, products, stocks... }
        │         }
        │
        ├─ Displays relateddata section
        │   ├─ Recipes (from payload)
        │   ├─ Products (from payload)
        │   ├─ Stocks (from payload)
        │   ├─ Purchases (from payload)
        │   └─ Movements (from payload)
        │
        └─► [APPROVE] button
            └─ InventoryApprovalService::executeItemDeletion()
                └─ DB::transaction {
                    [1] Query RecipeIngredient
                    [2] Delete RecipeIngredient
                    [3] Check Recipe integrity
                    [4] Delete Item
                    [5] Log audit trail
                    [6] Update ApprovalAuditRequest
                   }
AFTER DELETION
==============
Cascade Effects:
├─ Item: DELETED
├─ RecipeIngredient: DELETED
│   └─ (2 rows affected)
├─ Recipe: AFFECTED
│   └─ (Marked incomplete in audit log)
├─ Product: STAYS
│   └─ (Can't be produced, but stays active)
├─ Stock: DELETED
│   └─ (5 records deleted via cascade)
├─ StockMovement: DELETED
│   └─ (47 records deleted via cascade)
├─ PurchaseItem: DELETED
│   └─ (3 records deleted via cascade)
└─ AuditLog: CREATED
    └─ (4-5 audit entries created)

Error Scenarios
Scenario 1: Item Not Found
Admin clicks Approve
  │
  └─► InventoryApprovalService::executeItemDeletion()
      └─ Item::where('id', 5)->firstOrFail()
         └─ ❌ NOT FOUND (already deleted somehow)
            └─ Exception thrown
               └─ Transaction rolled back
                  └─ ApprovalAuditRequest stays PENDING
                     └─ Admin sees error: "Item no longer exists"
Scenario 2: Stock Still Has Active Movement
During Step 4: Delete Item
  │
  └─ Item::delete() called
     └─ Cascades to Stock deletion
        └─ Stock has foreign key to StockMovement
           └─ StockMovement also deletes (cascade configured)
              └─ ✅ SUCCESS (no error)
Scenario 3: Recipe in Production
Before deletion, user sees warning:
"⚠️ 2 Product(s) affected: Bread, Cake"
After deletion, ProductionRequest for "Bread" will:
  ├─ Find recipe for product
  │  └─ Recipe has 0 complete ingredients
  │     └─ Cannot start production
  │        └─ Error: "Recipe incomplete"
Admin must:
  1. Recreate recipe with new item OR
  2. Create new recipe for product OR
  3. Adjust product to use different recipe

Key Points
✅ What's Guaranteed:
All related data is shown before deletion
User can't accidentally delete without knowing impact
Admin can see exactly what will happen
Complete audit trail created
Transaction ensures atomicity (all or nothing)
⚠️ What Changes:
RecipeIngredients: Deleted
Recipes: Stay (marked incomplete in logs)
Products: Stay (can't be produced)
Stocks: Deleted
Movements: Deleted
Purchases: Affected but stay (PurchaseItem removed)
🔄 Recovery Options:
Check audit logs for what was deleted
Recreate recipes if needed
Assign new items to incomplete recipes (if Option 2)
Create new purchase orders if needed
