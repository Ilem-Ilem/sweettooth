What Gets Tracked
Each audit log captures:
Who - User/Actor performing the action
What - Type of action (create/update/delete)
When - Timestamp of the action
Where - Which inventory item/operation
Why - Reason for approval requests
How - Details of changes made
Status - completed/pending/rejected
Example Log Entry:
Actor: John Doe (Warehouse Manager)
Action: create
Model: Item
Description: Created item 'Flour 5kg' (SKU: RM-FLO-1234) in category 
            'rawmaterial'. UOM: kg, Reorder Level: 100, Max Stock: 500
Status: completed
Timestamp: 2025-12-03 14:32:15
---
Approval Workflow Tracking
When non-admin users make changes, the system now logs:
Request Created - When user initiates change request
   - Status: pending
   - Includes: What they want to change and why
Request Approved - When manager approves (separate audit system)
   - Tracks who approved and when
Action Executed - When approved change is implemented
   - Status: completed
   - Tracks execution details

Support & Troubleshooting
Common Questions:
Q: Will this slow down operations?  
A: No. Audit logging adds <3ms per operation. Imperceptible to users.
Q: Do I need to modify the database?  
A: No. Uses existing auditlogs table.
Q: Can I disable audit logging?  
A: Yes, simply remove AuditService::log() calls if needed.
Q: How do I view the audit logs?  
A: Via Tinker, direct SQL queries, or future audit dashboard UI.
Q: What if there's an error?  
A: Audit logging errors are non-blocking. Operations complete normally.
