Purchase Analytics Items Tab - Bug Fix
Date Fixed: December 5, 2025  
Issue: Items tab in Purchase Analytics not working  
URL: /branch-dashboard/analytics/purchase?bid=...
---
Problem Identified
The "Items" tab in the Purchase Analytics page was not displaying data properly. The issue was in the getTopPurchasedItems() method in the PurchaseAnalytics Livewire component.
Root Cause
File: /app/Livewire/BranchDashboard/Analytics/PurchaseAnalytics.php (line 176-193)
Issue: The query had two problems:
Improper eager loading with aggregation: The original code called with(['item', 'purchase']) at the beginning, then selectRaw() with aggregation functions, followed by groupBy(). This broke the relationship loading because:
   - with() is called before the aggregation
   - groupBy() is called after selectRaw()
   - A second with('purchase') is called after groupBy() (redundant)
Late relationship loading: Attempting to load relationships AFTER grouping results in unpredictable behavior
Original Code
php
public function getTopPurchasedItems()
{
    $branchId = $this->getBranchId();  
    return PurchaseItem::with(['item', 'purchase'])
        ->whereHas('purchase', function ($query) use ($branchId) {
            // ... filters
        })
        ->selectRaw('itemid, SUM(quantity) as totalquantity, SUM(totalcost) as totalcost')
        ->groupBy('itemid')
        ->orderByDesc('totalcost')
        ->limit(10)
        ->with('purchase')  // ❌ Duplicate/improper
        ->get();
}
---
Solution Applied
Fixed Code:
php
public function getTopPurchasedItems()
{
    $branchId = $this->getBranchId();  
    $items = PurchaseItem::select('itemid', DB::raw('SUM(quantity) as totalquantity, SUM(totalcost) as totalcost'))
        ->whereHas('purchase', function ($query) use ($branchId) {
            $query->where('branchid', $branchId)
                ->when($this->supplierFilter, fn($q) => $q->where('suppliername', 'like', '%' . $this->supplierFilter . '%'))
                ->when($this->paymentStatus, fn($q) => $q->where('paymentstatus', $this->paymentStatus))
                ->whereBetween('purchasedate', [$this->dateFrom, $this->dateTo]);
        })
        ->groupBy('itemid')
        ->orderByDesc('totalcost')
        ->limit(10)
        ->get();
    // ✅ Manually load the item relationship after aggregation
    $items->load('item');
    
    return $items;
}
Changes Made
Removed early with() call - Prevents relationship loading conflicts with aggregation
Used explicit select() - Clearer which columns are selected before aggregation
Removed duplicate ->with('purchase') - Not needed since we only need the item relationship
Added manual load('item') - Load the relationship AFTER aggregation completes
Proper grouping - Ensures all selected columns are aggregated correctly
Benefits
✅ Correct Data Display: Items now show with their names and quantities  
✅ No N+1 Queries: The load() method loads all items in a single query  
✅ Better Performance: Explicit select and proper relationship loading  
✅ Cleaner Code: Logical flow of aggregation → grouping → relationship loading

Query aggregates PurchaseItems:
   - Groups by itemid
   - Sums quantity and totalcost for each item

Results are fetched (10 top items by cost)

   - Executes single "WHERE IN" query to load all related Item records

Technical Details
Query Execution Flow
Before Fix (broken):
eager load with(['item', 'purchase']) ← Executed but then ignored by groupBy
whereHas() ← Filter by purchase criteria  
selectRaw() ← Select specific columns
groupBy() ← Group results (breaks early eager loading)
with('purchase') ← Late attempt to load (doesn't work properly)
get() ← Execute query
Result: Items without relationships ✗
After Fix (correct):
select('itemid', DB::raw(...)) ← Select specific columns
whereHas() ← Filter by purchase criteria
groupBy() ← Group results
get() ← Execute aggregated query
load('item') ← Load items in single query (uses IN clause)
Result: Items with relationships ✓
SQL Generated
Query Structure:
sql
SELECT 
    itemid, 
    SUM(quantity) as totalquantity, 
    SUM(totalcost) as totalcost
FROM purchaseitems
INNER JOIN purchases ON purchaseitems.purchaseid = purchases.id
WHERE 
    purchases.branchid = ?
    AND purchases.purchasedate BETWEEN ? AND ?
    AND (supplier filter if provided)
    AND (payment status filter if provided)
GROUP BY itemid
ORDER BY totalcost DESC
LIMIT 10
-- Then loads items:
SELECT  FROM items WHERE id IN (?, ?, ?, ...)

Additional Notes
Why load() instead of with()?
with() is an eager loading constraint set BEFORE query execution
load() is a lazy loading method called AFTER results are retrieved
For aggregated/grouped queries, we must load relationships AFTER grouping
load() uses collection loading (single "IN" query) for efficiency
Performance Impact
Before: Unknown (potentially broken)
After: 2 queries total
  - 1st: Aggregation query with joins and filters
  - 2nd: Load related items via IN clause
No N+1 problem: All items loaded in single query, not one-per-item

✅ Supplier name filter (supplierFilter)
