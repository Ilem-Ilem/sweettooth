✅ Issue 2: Reset Filters Button
Status: FIXED
What was done:
Added resetFilters() public method to component
Method resets all filter properties to defaults
Button appears only when filters are active ($isAnyFilterActive)
Shows success message when clicked
Button placed next to "Show/Close Filters" toggle
Implementation:
php
public function resetFilters()
{
    $this->dateFrom = now()->subDays(30)->format('Y-m-d');
    $this->dateTo = now()->format('Y-m-d');
    $this->movementType = '';
    $this->selectedItem = null;
    $this->searchTerm = '';
    $this->itemSearch = '';
    $this->filterShift = '';
    $this->filterDepartment = '';
    $this->resetPage();
    session()->flash('success', 'Filters reset successfully.');
}

---
✅ Issue 5: Shift/Department Filter Limitation
Status: ACKNOWLEDGED (Not breaking, but limited)
Current Behavior:
Shift/Department filters only work for ItemRequest movements
This is by design (other movement types don't have shift/department info)
Charts don't break because they aggregate all data before filtering
Note: Full fix would require database migration to add shift/department columns to StockMovement table. Current limitation is acceptable since:
Non-ItemRequest movements (Purchases, Manual adjustments) don't have shift info
Filters gracefully handle null values
No data is lost or corrupted
---
Real-Time Chart Updates
Charts are now REACTIVE:
Charts update instantly when filters change
Responds to all filter changes:
  - Date range changes
  - Movement type filter
  - Item selection
  - Shift filter
  - Department filter
  - Search term
How it works:
When any filter changes, updated() method dispatches chartsNeedUpdate event
JavaScript listener catches the event and calls updateCharts()
Charts are destroyed and recreated with new filtered data
Animation disabled for instant response
Only updates if charts are visible (checks for DOM element)
Performance optimized:
Charts only re-render when needed
Previous chart instances destroyed before creating new ones
Animation disabled for snappy response
Small 50ms delay to ensure data is available
Graceful fallback if data is empty
