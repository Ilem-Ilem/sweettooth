Preserving Recipes & Recipe Ingredients When Deleting Items
Current State
Current Migration (recipeingredients table):
php
$table->foreign('itemid')->references('id')->on('items')->onDelete('restrict');
This prevents deletion of items if they're used in recipes. Our current implementation deletes the RecipeIngredient records instead.
---
Option 1: Keep Current Behavior (Simpler, Recommended)
What happens: RecipeIngredients are deleted with the item, recipes become incomplete.
Pros:
✅ No database migration needed
✅ Cleaner: incomplete recipes are obvious
✅ Recipes are never left with null items
✅ Audit trail shows what was deleted
✅ Admins can easily fix by recreating recipes
Cons:
❌ Historical recipe data is lost
❌ Production history loses ingredient details
Current Code Location: InventoryApprovalService::executeItemDeletion()
Usage: Just use as-is. Delete the item, recipes are marked incomplete, audit logs created.
---
Option 2: Preserve Recipes with Nullable Items (Advanced)
What happens: RecipeIngredients survive with itemid = NULL, recipes stay intact but with missing ingredients.
Step 1: Create Migration

php artisan make:migration makeitemidnullableinrecipeingredientstable

public function getItemStatusAttribute(): string

    }

        return 'MISSING';
    }
    return 'ACTIVE';
}

Step 6: Update Deletion Logic to Track Properly
File: InventoryApprovalService::executeItemDeletion()
php
public static function executeItemDeletion(ApprovalAuditRequest $request, Employee $approver): void
{
    DB::transaction(function () use ($request, $approver) {
        $payload = $request->payload;
        $itemId = $payload['itemid'];
        $item = Item::where('id', $itemId)
            ->where('branchid', $request->branchid)
            ->firstOrFail();
        $itemName = $item->name;
        $itemSku = $item->sku;
        // Get affected recipes BEFORE deletion
        $affectedRecipeIds = \App\Models\RecipeIngredient::where('itemid', $itemId)
            ->pluck('recipeid')
            ->unique()
            ->toArray();
        // Option 2: Set itemid to null instead of deleting
        \App\Models\RecipeIngredient::where('itemid', $itemId)
            ->update([
                'itemid' => null,
                // Optional: store what was deleted for reference
                // 'deleteditemname' => $item->name,
            ]);
        // Check recipes for status
        foreach ($affectedRecipeIds as $recipeId) {
            $recipe = \App\Models\Recipe::find($recipeId);
            if ($recipe) {
                // Log the incomplete recipe
                AuditService::log(
                    $approver,
                    'update',
                    $recipe,
                    "Recipe ingredient deleted - ingredient '{$itemName}' no longer available. " .
                    "{$recipe->getIncompleteIngredientsCount()} ingredient(s) now missing. " .
                    "Recipe can still be viewed but cannot be produced.",
                    'completed'
                );
            }
        }
        // Delete the item
        $item->delete();
        // Log deletion with note about preserved recipes
        AuditService::log(
            $approver,
            'delete',
            $item,
            "Deleted item '{$itemName}' (SKU: {$itemSku}). Preserved: " .
            count($affectedRecipeIds) . " recipe(s) with " . 
            \App\Models\RecipeIngredient::whereNull('itemid')->count() . 
            " now-missing ingredient(s). Recipes remain in system but are incomplete.",
            'completed'
        );
        $request->update([
            'approverid' => $approver->id,
            'approvertype' => Employee::class,
            'status' => 'approved',
            'approvedat' => now(),
        ]);
    });
}

Recommendation
Use Option 1 (Current) If:
✅ You want simple, straightforward deletion
✅ Missing items should cause immediate recipe issues
✅ Historical accuracy is less important
✅ You want to force recipe cleanup
Use Option 2 If:
✅ You need historical recipe preservation
✅ You want flexible recovery options
✅ Production history must be complete
✅ You're willing to do a migration
