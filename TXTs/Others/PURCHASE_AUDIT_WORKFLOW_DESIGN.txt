Purchase Audit Workflow Design
Overview
Implement a draft-and-request approval system for purchases where:
For Regular Employees:
User creates and saves a purchase → Stored as DRAFT (no stock changes)
User reviews draft and requests approval → Request sent to auditor
Auditor reviews and approves → Stock and inventory updated
Auditor can reject → Draft remains for user to edit
For Super Admins:
User creates and saves a purchase → IMMEDIATELY creates purchase, updates stock and items in one go (no approval needed)
No draft state, no approval request workflow
---
Workflow States
Purchase States
draft - Created but not submitted for approval, no stock changes
pendingapproval - Submitted for approval, waiting for auditor
approved - Approved by auditor, stock/inventory updated
rejected - Rejected by auditor, returned to draft for editing

Implementation Pattern (Follows Items.php Pattern)
In save() method:
php
public function save()
{
    $this->validate();
    
    // Super admins bypass approval workflow
    if (issuperadmin()) {
        $this->executeImmediatePurchaseCreation(); // Creates with status='approved', updates stock
        return;
    }
    
    // Regular employees save as draft, then request approval
    $this->savePurchaseDraft(); // Creates with status='draft', no stock changes
    $this->showRequestModal = true; // Show modal to request approval
}
This pattern matches how Items.php works:
Super admins call executeImmediateSave() which creates and logs as 'completed'
Regular employees store pending data and show audit modal
---
Notes
Drafts are per-user (tracked via recordedby morph)
Super admins: Stock changes IMMEDIATELY (status = 'approved')
Regular employees: No stock changes until approval (status = 'draft' → 'pendingapproval' → 'approved')
Users can edit drafts before requesting approval
Auditors can reject with reason, returns to draft
Audit trail tracks all actions with status 'completed' (super admin) or 'pending' (employee)
