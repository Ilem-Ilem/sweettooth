How It Works Now
Purchase Workflow
Employee creates purchase draft
   └─ Purchase status: 'draft'
   
Employee requests approval
   └─ Purchase status: 'pendingapproval'
   
Auditor approves
   └─ PurchaseAuditApprovalService::approvePurchase()
      ├─ Update purchase status → 'approved'
      ├─ For each item:
      │  ├─ Create/get Stock
      │  ├─ Update average cost
      │  ├─ Increase quantityavailable
      │  └─ Create StockMovement ✓
      └─ Log to audit trail
   
Stock Movement Analytics shows data ✓
Manual Adjustment Workflow
Manager edits stock quantity
   └─ StockMovement created:
      ├─ type: 'adjustment'
      ├─ referencetype: null
      ├─ movedby: who did it
      ├─ quantitybefore/after: tracked
      └─ notes: reason
   
Stock Movement Analytics shows in 'adjustment' category ✓
Database Schema
Every stock movement records:
sql
INSERT INTO stockmovements (
    stockid,              -- Which stock was affected
    type,                  -- 'in', 'out', 'adjustment', 'transfer', 'damaged', 'return'
    quantity,              -- Amount moved
    quantitybefore,       -- Stock level before
    quantityafter,        -- Stock level after
    referencetype,        -- 'App\Models\Purchase' or null
    referenceid,          -- ID of purchase (if applicable)
    movedbytype,         -- 'App\Models\Employee' or 'App\Models\User'
    movedbyid,           -- ID of person who created movement
    movementdate,         -- When it happened
    notes,                 -- Description
    createdat,
    updatedat
)
