Purchase Component Final Fixes - Complete Summary
Issues Fixed
✅ UOM Auto-Select from Item
Issue: User had to manually select UOM in the purchase items table, even though each item has its own UOM.
Solution:
Added wire:change="updateItemUom({{ $index }}, $event.target.value)" to the item select dropdown
Created updateItemUom() method that auto-populates the UOM field when an item is selected
Updated item select options to display the item's UOM: {{ $availableItem->name }} ({{ $availableItem->uom }})
UOM field now auto-fills with the item's UOM value
✅ Validation Not Enforcing All Fields
Issue: Form validation worked for empty purchases but didn't validate individual item fields properly.
Solution:
Updated validation rules with stricter constraints:
  - quantity: min:0.01 (not min:0)
  - unitfobfc: min:0.01 (not min:0)
  - uom: min:1 (ensure non-empty string)
Changed input step values from step="1" to step="0.01" for quantity and unitfobfc
Added individual field error messages for each purchase item in the table:
  blade
  @error('purchaseItems.'.$index.'.itemid')
  @error('purchaseItems.'.$index.'.quantity')
  @error('purchaseItems.'.$index.'.uom')
  @error('purchaseItems.'.$index.'.unitfobfc')
  
✅ Purchase Button Not Working
Issue: The save button wasn't properly triggering or validation errors weren't displaying properly.
Solution:
Fixed button type from implicit to explicit type="button"
Added proper Livewire loading states with wire:loading.attr="disabled"
Added loading indicator showing "Saving..." with spinner
Kept modal open on validation errors (they now display inline)
Modal only closes on successful save
✅ Modal Closing on Validation Errors
Issue: Modal would close even when validation failed, hiding error messages.
Solution:
Implemented proper validation exception handling in the save() method
Modal stays open when ValidationException is thrown
Error messages display inline for each field
Only closes on successful creation
✅ Missing Status Filter
Issue: No way to filter purchases by approval status.
Solution:
Added filterStatus property to component
Added status filter dropdown in filters section with options:
  - All
  - Draft
  - Pending Approval
  - Approved
  - Rejected
Integrated into query: ->when($this->filterStatus, fn ($q) => $q->where('status', $this->filterStatus))
Added to resetFilters() method
✅ Inconsistent Error Handling
Issue: Using session()->flash() for errors inconsistent with rest of app using toast().
Solution:
Replaced all session()->flash('success', ...) with $this->toast()->success(...)->send()
Replaced all session()->flash('error', ...) with $this->toast()->error(...)->send()
Wrapped error-prone methods in try-catch blocks:
  - save() - Catches validation exceptions
  - requestPurchaseApproval() - Throws exceptions for invalid states
  - delete() - Throws exceptions for invalid states
  - All exceptions caught and shown as toast errors
Removed unreachable code (throw new \Exception() followed by session()->flash())
