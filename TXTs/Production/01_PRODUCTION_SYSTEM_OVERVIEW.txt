PRODUCTION MODULE - SYSTEM OVERVIEW
====================================

QUICK SUMMARY
=============
The Production module is a complex system managing kitchen operations, raw material tracking, 
recipe management, and product callbacks. It uses department-based routing and integrates 
with inventory & sales through multi-stage callback workflows.

System has GOOD callback model implementations but INCONSISTENT Livewire integration patterns.

CORE ENTITIES
=============

1. SHIFT (Production Shift)
   - Employee's work session in production
   - Links to Department (Production category)
   - Has many: DailyProduce, ProductionCallback, ProductionRequest

2. RECIPE
   - Formula for making products
   - Links: Product, Ingredients (through RecipeIngredient)
   - Used in DailyProduce tracking

3. DAILY PRODUCE
   - Production output per recipe per shift
   - Tracks: produced, consumed, spoiled, callback quantities
   - Auto-calculates: closing_quantity, variance

4. PRODUCT DISPATCH
   - Finished product sent from production to sales
   - Links: Shift, Recipe, Product
   - References original production

5. CALLBACKS (3 Types)

   A) ProductionCallback
      Purpose: Report damaged/defective items to inventory
      Source: Raw materials OR finished products
      Flow: pending → approved_by_inventory → completed (or rejected)
      Actor: Inventory approves
      Status enum: pending, approved_by_inventory, rejected, completed

   B) ProductDispatchCallback  
      Purpose: Return products from sales back to production
      Source: Sales returns from customer/damage
      Flow: pending → approved_by_production → received_by_production → completed
      Actor: Production approves, then marks received
      Status enum: pending, approved_by_production, received_by_production, completed

   C) ProductCallback (LEGACY - NOT ACTIVELY USED)
      Status: Deprecated, review for removal

APPROVAL WORKFLOW
=================

Production → Inventory Callback:
  1. Production employee creates callback (pending)
  2. Inventory approves → stock updated, status: approved_by_inventory
  3. Inventory marks as completed → status: completed
  (Optional) Inventory rejects → status: rejected

Sales → Production Callback:
  1. Sales employee creates callback (pending)
  2. Production approves → status: approved_by_production
  3. Production marks as received → status: received_by_production
  4. Production completes → stock updated, status: completed

Key difference:
  - Production→Inventory: approval AND stock update happen together
  - Sales→Production: approval and receipt are separate, completion triggers stock update
