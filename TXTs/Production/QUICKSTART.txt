CODE PATTERN TO USE
===================

INCORRECT (Current):
    $employeeId = auth('employees')->user()->id;
    $callback->approve($employeeId);

CORRECT (Should be):
    $actor = current_actor();
    $callback->approve($actor);

WHY: Tracks both Employee and User as actors (polymorphic).

KEY CONCEPTS IN 30 SECONDS
==========================

Polymorphic: Multiple models (Employee, User) can perform actions
             Tracked with: id + type (class name)

Callbacks:   Track issues between departments
             Production→Inventory: damaged items
             Sales→Production: product returns

Stock:       Updated by model methods, not UI components
             ProductionCallback.approve() includes update
             ProductDispatchCallback.completeWithStockUpdate() includes update

Actor:       current_actor() = currently logged in Employee or User
             Always use for polymorphic tracking

HELPER FUNCTIONS
================

Use this everywhere:
    $actor = current_actor();

Store in database like this:
    'recorded_by_id' => $actor->id,
    'recorded_by_type' => get_class($actor),

Retrieve in query:
    $callback->recordedBy  # Eloquent handles morphTo automatically


COMMON MISTAKES TO AVOID
=======================

❌ Only storing ID: recorded_by_id = 123
   ✅ Store with type: recorded_by_id = 123, recorded_by_type = "App\Models\Employee"

❌ Stock logic in Livewire: $product->update(...)
   ✅ Stock logic in model: $callback->completeWithStockUpdate()

❌ Using auth() directly: auth('employees')->user()
   ✅ Using helper: current_actor()

❌ Hard-coding status: where('status', 'approved')
   ✅ Using enum: where('status', 'approved_by_inventory')

❌ Forgetting eager loading: ProductionCallback::get()
   ✅ Loading relationships: ProductionCallback::with(['shift', 'recordedBy'])->get()
