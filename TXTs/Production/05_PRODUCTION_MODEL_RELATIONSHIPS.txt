MODEL: ProductionCallback
=========================

File: app/Models/ProductionCallback.php
Table: production_callbacks
Purpose: Track damaged/defective items reported from production to inventory

DATABASE COLUMNS:
-----------------
id                      BIGINT PRIMARY KEY
shift_id               BIGINT FK → shifts.id
source_type            VARCHAR (raw_material_from_stock | finished_product_reject)
item_id                UUID FK → items.id (nullable)
product_id             UUID FK → products.id (nullable)
recorded_by_id         UUID (polymorphic FK)
recorded_by_type       VARCHAR (polymorphic - App\Models\Employee or App\Models\User)
quantity               DECIMAL(12,2)
uom                    VARCHAR (unit of measure)
reason                 VARCHAR (ENUM value: damage|expired|quality|contamination|etc)
status                 VARCHAR (pending|approved_by_inventory|rejected|completed)
approved_by_id         UUID (nullable, polymorphic FK)
approved_by_type       VARCHAR (nullable, polymorphic)
approved_at            TIMESTAMP (nullable)
notes                  LONGTEXT (nullable)
callback_time          TIMESTAMP (when callback was created)
created_at             TIMESTAMP
updated_at             TIMESTAMP

METHODS:
--------

TYPE CHECKERS:
  
  isRawMaterial(): bool
    - Returns true if source_type === 'raw_material_from_stock'
    - Usage: if ($callback->isRawMaterial()) { ... }
  
  isFinishedProduct(): bool
    - Returns true if source_type === 'finished_product_reject'
    - Usage: if ($callback->isFinishedProduct()) { ... }

STATE CHECKERS:

  canBeApproved(): bool
    - Returns true if status === 'pending'
    - Usage: if ($callback->canBeApproved()) { ... }
    - Prevents invalid state transitions

ACTIONS:

  approve($actor = null): bool
    Purpose: Approve callback and update stock
    Parameters:
      - $actor (optional): User or Employee object
      - If not provided, uses current_actor()
    Returns: true on success, false if can't be approved
    Side Effects:
      - Updates stock (raw material or finished product)
      - Sets status to 'approved_by_inventory'
      - Records approved_by_id, approved_by_type
      - Records approved_at timestamp
    
    Throws:
      - RuntimeException if no actor and current_actor() is null
      - InvalidArgumentException if missing item_id or product_id
      - RuntimeException if Stock/DailyProduce not found
    
    Usage:
      $actor = current_actor();
      $callback->approve($actor);
      // or
      $callback->approve();  // Uses current_actor()

  reject($actor = null, $reason = null): bool
    Purpose: Reject callback (don't update stock)
    Parameters:
      - $actor (optional): User or Employee object
      - $reason (optional): String explanation for rejection
    Returns: true on success, false if can't be rejected
    Side Effects:
      - Sets status to 'rejected'
      - Appends rejection reason to notes
      - Records approved_by_id, approved_by_type
      - Records approved_at timestamp
    
    Usage:
      $callback->reject(current_actor(), 'Already processed');

  complete(): bool
    Purpose: Mark callback as completed (can't update stock anymore)
    Returns: true on success, false if status isn't 'approved_by_inventory'
    Side Effects:
      - Sets status to 'completed'
    
    Note: For finished products, completion is automatic with approval
    
    Usage:
      $callback->complete();

STOCK UPDATE METHODS (Private, called from approve()):

  updateRawMaterialStock(): void
    Purpose: Adjust Stock table for raw material callbacks
    Implementation:
      - Finds Stock record by item_id and branch_id
      - Decreases quantity_available
      - Increases quantity_damaged
      - Creates StockMovement record for audit trail
    
    Throws:
      - InvalidArgumentException if item_id is missing
      - RuntimeException if Stock record not found
    
    Example impact:
      Before: quantity_available = 100, quantity_damaged = 10
      After:  quantity_available = 95,  quantity_damaged = 15
      (if callback quantity = 5)

  updateFinishedProductStock(): void
    Purpose: Adjust DailyProduce for finished product callbacks
    Implementation:
      - Finds DailyProduce by shift_id and recipe_id
      - Increases callback_quantity
      - Recalculates closing_quantity and variance
    
    Throws:
      - InvalidArgumentException if product_id is missing
      - RuntimeException if Recipe or DailyProduce not found
    
    Example impact:
      Before: callback_quantity = 0,  closing_quantity = 100
      After:  callback_quantity = 5,  closing_quantity = 105

VALIDATION METHODS:

  validateQuantity(): bool
    Purpose: Ensure callback quantity doesn't exceed limits
    Behavior:
      - Raw materials: No validation (may be partially used)
      - Finished products: Must not exceed produced_quantity
    
    Throws:
      - InvalidArgumentException if product_id missing
      - RuntimeException if DailyProduce not found
      - ValidationException if quantity exceeds limit
    
    Called automatically on create/update via boot() method

ATTRIBUTE ACCESSORS:

  $callback->formatted_source_type
    Returns: "Raw Material From Stock" or "Finished Product Reject"
    Implementation: ucwords(str_replace('_', ' ', $source_type))

  $callback->formatted_reason
    Returns: "Damage" or "Quality Issue"
    Implementation: ucwords(str_replace('_', ' ', $reason))

  $callback->formatted_status
    Returns: "Pending" or "Approved By Inventory"
    Implementation: ucwords(str_replace('_', ' ', $status))

  $callback->item_name
    Returns: Item name or Product name (depending on type)
    Logic:
      - If raw_material: returns $callback->item->name
      - If finished_product: returns $callback->product->name
      - Otherwise: returns "Unknown"

METHODS:
--------

STATE CHECKERS:

  canBeApproved(): bool
    - Returns true if status === 'pending'

  canBeReceived(): bool
    - Returns true if status === 'approved_by_production'

ACTIONS:

  approve($actor = null): bool
    Purpose: Approve return from sales
    Updates:
      - status → 'approved_by_production'
      - approved_by_id, approved_by_type, approved_at
    
    Usage:
      $callback->approve(current_actor());

  markAsReceived($actor = null): bool
    Purpose: Production marks return as received
    Updates:
      - status → 'received_by_production'
      - received_by_id, received_by_type, received_at
    
    Usage:
      $callback->markAsReceived(current_actor());

  complete(): bool
    Purpose: Mark completion (without stock update)
    Updates:
      - status → 'completed'
    
    Note: Don't use this directly! Use completeWithStockUpdate()

  completeWithStockUpdate(): bool [IMPORTANT]
    Purpose: Complete callback AND update stock records
    Side Effects:
      1. Updates ProductStock (sales inventory)
         - Increments callback_quantity
      2. Updates DailyProduce (production inventory)
         - Increments callback_quantity
         - Increments closing_quantity
         - Recalculates variance
      3. Sets status to 'completed'
    
    Throws:
      - RuntimeException if status isn't 'received_by_production'
      - RuntimeException if ProductStock not found
      - RuntimeException if DailyProduce not found
    
    Usage:
      $callback->completeWithStockUpdate();

VALIDATION METHODS:

  validateQuantity(): bool
    Purpose: Ensure callback quantity doesn't exceed dispatch quantity
    Logic:
      - If product_dispatch_id is NULL (orphaned): return true
      - Sum all other callbacks for same dispatch
      - Check: total_callbacks + new_quantity <= received_quantity
    
    Throws:
      - RuntimeException if dispatch not found
      - ValidationException if quantity exceeds available
    
    Called automatically on create/update

STOCK UPDATE METHODS (Private):

  updateProductStock(): void
    Purpose: Increase callback_quantity in ProductStock
    Implementation:
      - Finds ProductStock by sales_shift_id and product_id
      - Increments callback_quantity by callback quantity
      - Uses lockForUpdate() to prevent race conditions

  updateDailyProduce(): void
    Purpose: Increase callback_quantity in DailyProduce
    Implementation:
      - Finds DailyProduce by original shift and recipe
      - Increments callback_quantity and closing_quantity
      - Calls updateCalculations() to recalculate variance
      - Logs warning if DailyProduce not found (doesn't fail)

ATTRIBUTE ACCESSORS:

  $callback->formatted_reason
    Returns: "Expired" or "Quality Issue"

  $callback->formatted_status
    Returns: "Pending" or "Approved By Production"

POLYMORPHIC RELATIONSHIPS DETAILED
===================================

What is Polymorphic?
  Multiple models can be associated through the same relationship.
  Example: Both Employee and User can approve a callback.

Implementation in ProductionCallback:

  Column: recorded_by_type + recorded_by_id
  
  Schema:
    recorded_by_id INT        -- The ID of the approver
    recorded_by_type VARCHAR  -- The class name: App\Models\Employee or App\Models\User

  Model:
    public function recordedBy(): MorphTo
    {
        return $this->morphTo('recorded_by', 'recorded_by_type', 'recorded_by_id');
    }

  Usage:
    $callback = ProductionCallback::first();
    $callback->recorded_by_type;  // "App\Models\Employee"
    $callback->recordedBy;        // Employee object
    $callback->recordedBy->name;  // "John Doe"

  Storage:
    Insert:
      recorded_by_id = 123
      recorded_by_type = "App\Models\Employee"
    
    Or:
      recorded_by_id = 456
      recorded_by_type = "App\Models\User"

  Querying:
    // Get all callbacks recorded by any Employee
    $callbacks = ProductionCallback::where('recorded_by_type', Employee::class)
        ->get();

Inverse Relationship (in Employee and User models):

  In Employee:
    public function productionCallbacks()
    {
        return $this->morphMany(ProductionCallback::class, 'recorded_by');
    }
  
  In User:
    public function productionCallbacks()
    {
        return $this->morphMany(ProductionCallback::class, 'recorded_by');
    }

  Usage:
    $employee = Employee::find(123);
    $callbacks = $employee->productionCallbacks()->get();
