Universal Approval Workflow - Quick Start Guide
TL;DR: Add one trait to any component → instant approval workflow for all actions.
---
30-Second Setup
Step 1: Add Trait to Your Component
php
namespace App\Livewire\BranchDashboard\Inventory;
use Livewire\Component;
use App\Traits\RequiresApprovalWorkflow;  // ← Add this
class Items extends Component
{
    use RequiresApprovalWorkflow;  // ← Add this
    
    // ... rest of component
}
Step 2: Call submitForApproval() Instead of Direct Save
Before:
php
public function saveItem()
{
    $this->validate([...]);
    
    Item::create([
        'name' => $this->name,
        'sku' => $this->sku,
        'cost' => $this->cost,
    ]);
    
    $this->dispatch('toast', message: 'Item created');
}
After:
php
public function saveItem()
{
    $this->validate([...]);
    
    // Call submitForApproval instead
    $result = $this->submitForApproval(
        'create',                    // Action
        'item',                      // Resource type
        null,                        // Resource ID (null for create)
        [                            // Payload (exact data)
            'name' => $this->name,
            'sku' => $this->sku,
            'cost' => $this->cost,
        ],
        'New item for bakery'        // Reason
    );
    
    $this->dispatch('toast', message: $result['message']);
}
Step 3: Show Reason Modal (Optional but Recommended)
blade
{{-- In your view --}}
@if($showReasonModal)
<div class="modal">
    <textarea wire:model="reason" placeholder="Why do you need this?"></textarea>
    <button wire:click="submitRequest" class="btn-primary">Submit</button>
</div>
@endif
php
public function saveItem()
{
    $this->validate([...]);
    
    // For non-super-admins, show reason modal
    if (!$this->isSuperAdmin()) {
        $this->showReasonModal = true;
        return;  // Stop here, wait for submitRequest()
    }
    
    // For super admins, process immediately
    $this->executeCreate();
}
public function submitRequest()
{
    $this->validate(['reason' => 'required|min:10']);
    
    $result = $this->submitForApproval(
        'create',
        'item',
        null,
        [...payload...],
        $this->reason
    );
    
    if (!$result['approved']) {
        $this->resetForm();
    }
}

🎯 The Four Actions
| Action | When Used | Resource ID | Example |
|--------|-----------|------------|---------|
| create | Add new | null | Add new item to inventory |
| update | Edit existing | UUID | Change item price |
| delete | Remove | UUID | Delete supplier |
| adjust | Quantity/price change | UUID | Recount stock |

📝 Common Use Cases
CREATE (Add New Item)
php
$this->submitForApproval(
    'create',
    'item',
    null,
    [
        'name' => 'Sugar 50kg',
        'sku' => 'SUGAR-50',
        'cost' => 5000,
        'categoryid' => 1,
    ],
    'New item for bakery department'
);
UPDATE (Edit Product Price)
php
$this->submitForApproval(
    'update',
    'product',
    $product->id,        // ← Need the ID
    [
        'price' => 5500,
        'cost' => 2700,
    ],
    'Price adjustment after cost review'
);
DELETE (Remove Supplier)
php
$this->submitForApproval(
    'delete',
    'supplier',
    $supplier->id,       // ← Need the ID
    [
        'id' => $supplier->id,
        'name' => $supplier->name,  // Include data for reference
    ],
    'Discontinuing old supplier, moving to new vendor'
);
ADJUST (Stock Count)
php
$this->submitForApproval(
    'adjust',
    'stock',
    $stock->id,          // ← Need the ID
    [
        'quantity' => 500,
        'previousquantity' => 200,
        'adjustment' => 300,
    ],
    'Recount after physical stock take'
);

🔄 What Happens Next
If User is Super Admin
Action executes immediately
No modal, no waiting
Toast: "Item created successfully"
Logged to auditlogs with status "completed"
If User is Regular Employee
Validation runs - "Saving..." spinner shown
Form closes - Modal appears:
   
   ┌──────────────────────┐
   │ Why Are You Requesting? │
   │                        │
   │ [    reason textarea   ] │
   │                        │
   │ [Cancel]  [Submit]     │
   └──────────────────────┘
   
User types reason and clicks [Submit]
Request created in approvalauditrequests table
Toast: "Your request has been submitted for approval"
Admin sees request in /branch-dashboard/audit-management
Admin clicks [Approve]
Action executes with exact stored data
Logged to auditlogs with status "completed"

🧪 Testing
Test 1: Create as Regular Employee

// Login as regular employee
$this->actingAs($employee, 'employees');
// Call saveItem
$component = $this->component('Items')
    ->set('name', 'Sugar 50kg')
    ->set('sku', 'SUGAR-50')
    ->set('cost', 5000);
$component->call('saveItem');

    ApprovalAuditRequest::where('action', 'like', 'create:item%')->exists()
);
$this->assertFalse(
    Item::where('sku', 'SUGAR-50')->exists()
);

php

$this->actingAs($superAdmin, 'employees');
$component = $this->component('Items')
    ->set('name', 'Sugar 50kg')
    ->set('sku', 'SUGAR-50')
    ->set('cost', 5000);
$component->call('saveItem');
// Should create item immediately, NO approval request
$this->assertTrue(
    Item::where('sku', 'SUGAR-50')->exists()
);
$this->assertFalse(

Test 3: Admin Approves

🔍 Return Value
All calls return an array:
php
$result = $this->submitForApproval(...);
$result['approved']    // bool - true if super admin, false if approval needed
$result['requestid']  // int|null - request ID if approval needed, null if super admin
$result['message']     // string - "Item created successfully" or "Request submitted for approval"
Use it to decide what to show user:
php
$result = $this->submitForApproval(...);
if ($result['approved']) {
    $this->dispatch('toast', message: $result['message'], type: 'success');
} else {
    $this->dispatch('toast', message: $result['message'], type: 'info');
    // Optionally store request ID: $this->requestId = $result['requestid'];
}

❌ Common Mistakes
❌ Not Checking Super Admin First
php
// WRONG - Always shows reason modal
public function saveItem() {
    $result = $this->submitForApproval(...);
    // Super admin forced to see modal
}
// RIGHT - Super admin bypassed
public function saveItem() {
    if ($this->isSuperAdmin()) {
        $this->executeCreate();  // Direct execution
        return;
    }
    
    // Regular user sees modal
    $this->showReasonModal = true;
}
❌ Forgetting Resource ID for Update/Delete
php
// WRONG - will crash
$this->submitForApproval('update', 'item', null, [...]);
// RIGHT - include resource ID
$this->submitForApproval('update', 'item', $item->id, [...]);
❌ Putting Extra Data in Payload
php
// WRONG - uistatus and debug won't be saved
$this->submitForApproval('create', 'item', null, [
    'name' => 'Item',
    'uistatus' => 'showing',      // ❌ Not a model field
    'debug' => true,               // ❌ Not a model field
]);
// RIGHT - only include actual model fields
$this->submitForApproval('create', 'item', null, [
    'name' => 'Item',              // ✅ Fillable
    'sku' => 'ITEM-1',            // ✅ Fillable
    'cost' => 1000,               // ✅ Fillable
]);

🐛 Troubleshooting
"Unknown resource type: 'xyz'"
Solution: Add the type to getModelClass() in the trait or override it in your component.
"Resource ID required for update"
Solution: Make sure you're passing the resource ID for update/delete/adjust:
php
$this->submitForApproval('update', 'item', $item->id, [...]);  // ✅ Has ID
$this->submitForApproval('update', 'item', null, [...]);       // ❌ Missing ID
Super admin seeing reason modal
Solution: Check isSuperAdmin() BEFORE calling submitForApproval():
php
if ($this->isSuperAdmin()) {
    $this->executeCreate();  // Direct execution
} else {
    $this->showReasonModal = true;  // Show modal
}
Request not executing after approval
Solution: Check that AuditManagement/Index.php is calling executeApprovedAction() and submitForApproval() format matches the parser.
