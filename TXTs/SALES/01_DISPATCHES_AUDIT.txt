OVERVIEW
--------
Module handles receiving of products dispatched from Production to Sales.
Displays dispatches with status tracking and variance monitoring.

CURRENT FUNCTIONALITY
---------------------
1. Display dispatches filtered by:
   - Status (dispatched, received, rejected)
   - Date
   - Search (product name/SKU)

2. Receiving workflow:
   - Open receiving modal
   - Enter received quantity
   - Add receiving notes
   - Auto-fill with dispatched quantity

3. Stock integration:
   - Updates ProductStock table on receipt
   - Calculates expiry dates from production_date + shelf_life_days
   - Adds received quantities to addition_quantity (non-opening stock)

4. Variance tracking:
   - Calculates variance: received_quantity - dispatched_quantity
   - Shows variance warnings

WORKFLOW GAPS
-------------

1. No email/notification on dispatch received
2. No audit trail of who approved/rejected dispatch
3. No variance root cause tracking
4. No re-dispatch workflow for rejected items
5. No bulk receiving capability

DATA INTEGRITY ISSUES
---------------------

1. Production date source could be ambiguous
   - Uses dailyProduce.production_date if available
   - Falls back to today() which may be incorrect

2. Stock calculations:
   - addition_quantity receives the received quantity
   - But closing_quantity is set to received quantity initially
   - Should opening + additions = closing initially (before sales)

RECOMMENDATIONS
---------------

1. Rename all references from "Kitchen Dispatch" to "Production Dispatch"
2. Add shift validation - ensure dispatch shift_type matches active shift
3. Add stock opening verification before allowing dispatch receipt
4. Create ProductDispatchCallback model for tracking callbacks from sales
5. Add variance reason field to track why dispatches have variance
6. Implement audit trail for all dispatch status changes
7. Add re-dispatch workflow for rejected dispatches

DEPENDENT MODELS/RELATIONSHIPS
------------------------------

ProductDispatch model needs:
- dailyProduce relationship (working)
- dispatchedBy relationship (working)
- receivedBy relationship (working)
- shift_type field or relationship

ProductStock model:
- Called on dispatch receipt
- Sets addition_quantity (non-opening stock added during shift)
- Calculates closing_quantity = opening + additions - sold

Department model:
- Used to identify sales department
- Loaded from slug or employee's department

RELATED COMPONENTS

1. Production: DailyProduce/Index.php - creates dispatches
